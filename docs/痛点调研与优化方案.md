# 电视直播 APP 痛点调研与优化方案（聚源TV）

> 本文档沉淀"调研 → 根因 → 优化 → 验证"全链路结论，作为本仓库体验优化工作的依据与交付物。
> 适用版本：v2.5.0（versionCode 250）

## 一、调研背景

真实用户反馈的三大问题：

1. 电视安装后**首次进入极慢**，卡在"解析源"近一分钟，随后画面一闪而过、**比例不对**，播放不起来；
2. **解析源卡住时直接退出**，再次进入直接黑屏把电视卡死；
3. 要求**全界面中文**、**所有源在国内网络可用**。

## 二、行业普遍痛点与解法对照

| 痛点 | 行业常见根因 | 主流解法 | 本 APP 处理 |
|---|---|---|---|
| 首次启动/换源慢，卡"解析源" | 弱网无超时、源站串行下载、UI 线程同步解析、失效镜像 | 并发下载 + 超时保护 + 后台解析 + 本地缓存 | 45s 总超时、源内容 24h 缓存、频道解析结果文件缓存、首启降载（只探测前 200 台） |
| 重进黑屏卡电视 | 竞态崩溃、异常处理自杀进程、播放器释放策略不当、大缓存拖慢启动 | 就绪保护、不自杀、暂停不释放、缓存移出 SP | updateConfig context 就绪保护、异常处理器不自杀、onStop 只暂停、大字符串改文件缓存 |
| 画面比例不对 | 全屏拉伸（stretch）、缺少按原始比例留黑边 | RESIZE_MODE_FIT / 等比留边 | 全屏/非全屏均 FIT，4:3/21:9 源不变形 |
| 切台慢/闪屏 | 无预加载、缓冲策略差 | 备用播放器预准备下一频道 | standbyPlayer 后台预加载下一频道、低缓冲策略（500ms 出画面）、连接预热 |
| 无限重试刷屏卡顿 | 列表未就绪时循环请求焦点 | 重试次数上限 + 附着/判空保护 | ListAdapter 5 次上限、MenuFragment 10 次上限 |
| 国内网络不可用 | 默认源被墙（jsDelivr 等）、GitHub 直连不稳 | 国内镜像 + 多镜像轮换 | 默认源重排 6 个国内可用源、GitHub 镜像优先 + 原地址兜底 |
| 界面非中文 | 默认语言英文、分组名取源数据英文 | 默认中文字符串 + 分类映射 | values/strings.xml 中文化（175 key）、30 个英文分组映射 |
| 解析提示刷屏 | 多源并行导入重复弹 Toast | 会话级去重 | AtomicBoolean 只弹一次"解析源" |

## 三、本 APP 根因定位（代码级）

### 3.1 首启慢 / 解析源卡（问题 1 前段）

- `Utils.getUrls()`：镜像列表含已失效域名（ghproxy.com、github.moeyy.cn、ghproxy.net），命中即长时间等待；
- `DownGithubPrivate.downloadFile()`：无总超时，单个请求可无限挂起，与用户"卡近一分钟"现象吻合；
- 修复：镜像按国内可用性重排（moeyy.xyz、ghfast.top、gh-proxy 等），公共 GitHub URL 镜像优先 + 原地址兜底；下载增加 `totalTimeoutMs = 45_000` 总超时。

### 3.2 重进黑屏卡死（问题 2）

- 竞态：重进时 `ready()` 早于 `init()`；
- 异常处理器直接 `killProcess` 自杀；
- `onStop` 释放播放器导致 HOME 往返重建；
- 修复：`updateConfig` context 就绪保护、异常处理器不再自杀、`onStop` 只暂停不释放、大缓存字符串迁出 SharedPreferences。

### 3.3 画面比例不对（问题 1 中段）

- `PlayerFragment.updatePlayerViewLayout()` 强制全屏拉伸；
- 修复：统一 `RESIZE_MODE_FIT` + 居中留黑边；PiP 按视频实际宽高比（`player.videoSize`）计算，21:9/4:3 均有兜底。

### 3.4 无限重试刷屏（体验劣化）

- `ListAdapter.toPosition()`：itemCount==0 或未附着时无限 `post` 重试，实测 20 次/秒；
- `MenuFragment.onVisible()`：同样无限重试；
- 修复：分别加 5 次/10 次上限 + `isAttachedToWindow` + `itemCount>0` 判空。

### 3.5 国内网络可用性（问题 3）

- 默认源含被墙的 jsDelivr；GitHub raw 直连在国内不稳定；
- 修复：`SP.DEFAULT_SOURCES` 重排为 6 个国内直连/官方域名源；GitHub 拉取走镜像链；EPG 默认 `live.fanmingming.cn` 国内域名优先。

## 六、遗留风险与后续建议

1. **镜像可用性随时间变化**：当前网络下 moeyy.xyz/ghfast.top/gh-proxy 部分返回 403/404。建议在真实国内宽带上验证，必要时扩充镜像候选或改为运行时探测选优；
2. **EPG 源稳定性**：fanmingming e.xml 在本环境不可达，需真机确认；可增加 EPG 多源健康度标记；
3. **后续可做**：源健康度主动探测并展示（当前仅播放失败时动态标记）、切台预测预加载扩展到"常用频道"、分组映射支持用户自定义；
4. **发布流程**：版本号统一为 versionCode=250（version.json 与 build.gradle 一致），避免旧编码 20409 恒判"有新版本"。
 
 ## 七、v2.6.0 频道分类 + 多源聚合 + 弹窗治理
 
 ### 7.1 弹窗刷屏（用户反馈：观看中不断弹出解析弹窗）
 
 - 根因：多源导入/解析/失败路径多处直接 `Toast.show()`，无节流，弱网下同文案反复弹；
 - 修复一：`YourTVApplication.toast()` 全局节流（ConcurrentHashMap 记录，同文案 8 秒最多 1 条）；
 - 修复二：`importFromUrl` 新增 `silent` 参数，自动导入/聚合阶段源失败静默跳过（不弹"下载在线直播源失败"），仅手动切源/刷新保留提示；
 - 实测：连续观看 60 秒仅 1 条 Toast 日志；全新安装 10 秒内无失败弹窗。
 
 ### 7.2 频道分类（用户反馈：分类不合理，参考电视家）
 
 - 新增 `ChannelClassifier`：央视（CCTV/CGTN 台号规范化 cctv1…cctv17）/ 港澳台（台湾/香港/澳门品牌库+英文兜底）/ 地方卫视 / 地方频道（33 省 + 近 400 城市 → 省份映射，含港澳台）/ 海外频道（约 80 国家/地区关键词库）/ 其他；
 - 侧栏分组：央视 → 卫视 → 省份（按行政区划排序）→ 国家 → 其他；频道列表固定排序，默认频道落在 CCTV1；
 - `mergeKey()` 跨源合并：CCTV 用台号（CCTV-1综合 与 CCTV1 合并）、卫视/地方/海外用规范名（去括号/清晰度后缀/标点）、其他叠加原分组；`canonicalAlias()` 英文→中文（Hunan TV→湖南卫视、TVB Jade→翡翠台 等），并新增 BRTV 北京卫视→北京卫视 别名（北京卫视 10→11 条线路）。
 
 ### 7.3 单源频道不可用（用户反馈：部分频道仅 1 个不可用源）
 
 - 多源聚合：首源导入成功后后台并发导入全部预置源（每源 50s 兜底超时），按"分类+规范名"合并去重，央视/主流卫视线路 10~30 条，按清晰度（URL 关键词+实测分辨率）降序，坏线由运行时健康探测/播放失败自动跳过；
 - 源列表修正：移除失效的 YueChan APTV.m3u（404，实际文件为组播 IPTV.m3u）与区域封锁的 wcb1969（GitHub 451）、fanmingming.com ipv4（404）；新增 best-fan cn_province/cn_cctv 专项源，默认 13 个源全部国内直连或 GitHub 镜像可加速；
 - 实测聚合：9~12 源 / 643~644 频道；CCTV1=20、CCTV4=23、CCTV5=29、CCTV1-17 全部 ≥13；主流卫视湖南 17/东方 20/浙江 13/广东 13/北京 11/天津 18/山东 18/四川 16 等 ≥10；江苏卫视 9 条为当前公开源生态的上限（跨 5 源真并集，无合并遗漏）。
 
 ### 7.4 附带修复（深度检视）
 
 - 激活源缓存缺失时不再自动 `switchSource(0)` 整体替换频道列表（避免聚合结果被内置源覆盖）；"已是当前源"不再误报"加载失败"（改用 aready_current_source 文案）；
 - 聚合静默导入（apply=false）不再并发写入 `active_source`（竞态会把激活源指向随机源，实测指向 APTV.txt），首源导入后才移动激活源；
 - 频道缓存写改为同步写，消除 WRONG_FINAL_BLOCK_LENGTH 半截文件。
 
 ### 7.5 v2.6.0 验证证据

## 八、v2.7.0 三级分级列表 + 高质量源集成

### 8.1 三级分级频道列表（用户要求：央视/卫视/地方/海外/其他为一级）

- 一级分类固定为 央视 / 卫视 / 地方 / 海外 / 其他（另有 我的收藏/全部频道 两个特殊分组）；
- 央视、卫视两级直达频道（一级=央视，二级=频道本身）；
- 地方（二级=省份，含港澳台与"未分类"兜底）、海外（二级=国家/地区）、其他（二级=分类）为三级；
- 交互：右键/确认键下钻地区列表，左键/返回键逐级退回，菜单顶部路径提示实时显示"地方 › 河北"；
- 实现：`TVGroupModel` 新增导航状态（NavEntry + enterCategory/exitCategory/restoreNav），`GroupAdapter` 按导航条目渲染，`MenuFragment` 处理下钻/返回/路径，`ChannelClassifier.topCategoryOfGroup` 提供分组→一级分类映射；
- 修复：播放频道定位到真实分组（原逻辑停留在"全部频道"导致重开菜单导航错乱）；同一 BACK 事件被 Activity.onKey 与 OnBackPressedDispatcher 双分发导致"退出下钻即关菜单"，用一次性标志幂等处理；路径提示与焦点分组同步（焦点回调先于 setPosition 执行，需显式传分组索引）。

### 8.2 高质量源调研与集成（用户要求：咪咕4K源质量高，继续调研集成）

- 调研结论（实测）：zbds.top（750 台）、best-fan 系列（881 台）为原有主力；新发现并实测：
  - `jk2024988/TV2024 咪咕2.m3u`：62 台全咪咕直播（CCTV1-17/卫视/地方），仓库活跃（2026-07 更新，932 star）；
  - `hououinkami/AppleTV China_v4.m3u`：咪咕 aikan.miguvideo.com CCTV1-17 + APTV bestv 8M 卫视，每日维护（2026-08-07 更新）；
  - `zhmzjj310144/migu-sports 三源合并_央视体育地方综合源.m3u`：492 台，含浙江卫视4K（ali-xwl.cztv.com）、湖南卫视4K（mgtv）、卫视超清、地方台；
