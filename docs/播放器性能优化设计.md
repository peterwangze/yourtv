# 启动与切台性能优化设计（v3.0.0 多播放器快速加载）

> 目标：打开应用到电视画面、遥控切台的速度对齐主流电视直播应用；
> 方案：播放器池（主+备用）预加载相邻频道 + 播放器复用 + 连接预热 + 启动故障快速恢复。

## 一、主流电视直播应用的做法调研（2026-08）

电视家、小鲸直播、火星直播、HDP 等主流电视直播应用的核心体验做法（它们靠广告/会员变现，
但播放体验本身是留存关键）：

1. **播放器复用**：主播放器常驻，切台只换媒体源，绝不反复创建/释放播放器。
   本应用 v2.9 之前：冷切路径复用，但秒切路径会 release 旧播放器。
2. **相邻频道预加载**：备用播放器（0-1 个为主，极少 2 个）预加载上/下一频道到 READY，
   切台无缝接管。本应用 v2.9 之前：仅触屏设备启用，电视上完全关闭。
3. **低缓冲秒开**：播放缓冲 500ms~1s，不等默认 2.5s。本应用已有。
4. **连接池预热**：共享 OkHttp 连接池，切台前预连接目标服务器。
   本应用已有 prewarm，但仅触屏调用。
5. **首帧快速恢复**：启动时最后频道/稳定源立即播放；失效线路快速跳过，不黑屏等待。
   本应用 v2.9 之前：稳定源失效会被 30s 冷却 + 自动换源开关（默认关）双重拦截。
6. **后台探测降载**：全量线路探测不在启动时抢占带宽。本应用 v2.9 之前：启动即 200 路并发探测。

## 二、当前实现瓶颈（对照定位）

1. **电视上无备用播放器**：`prepareStandbyForNextChannel()` 以 `isTouchScreenDevice()` 直接 return，
   电视端每次切台都是冷启动（建源→拉流→解码），2~5s 是常态；
2. **秒切路径释放旧播放器**：`old?.release()` 后每次秒切都新建备用播放器，解码器反复创建；
3. **备用播放器丢失请求头**：`MediaItem.fromUri(url)` 不携带 Referer/User-Agent，依赖头的线路预加载必失败；
4. **备用播放器不选线**：只预加载首条线路，首线坏则预加载失败；
5. **启动黑屏 30s**：稳定源线路失效时，`onPlayerError` 被 30s retryCooldown 与
   `autoSwitchSource=false` 双重拦截，直到 checkPlaybackRunnable 冷却结束才换线；
6. **全量探测抢占带宽**：列表应用后立即 200 路并发探测，与首帧拉流抢带宽。

## 三、v3.0.0 设计：多播放器池 + 启动快速恢复

### 3.1 播放器池（主 + 备用，角色交换复用）

- `ensurePlayerPool()`：启动时创建两个 ExoPlayer（主播放器 + 备用播放器），常驻不释放；
- 备用播放器在所有设备启用（设置"快速切台"默认开，弱机可关）；
- 预加载目标：当前频道的下一频道（全列表顺序 = 遥控切台顺序），选线与主播放器一致
  （跳过已探测坏线，取质量分最高线路），`prepare()` 到 READY 停在首帧（不持续拉流）；
- 切台到已就绪目标 → 角色交换（`player` 与 `standbyPlayer` 引用互换、视图重绑），
  0 延迟接管；旧播放器直接复用为新的备用槽，预加载新的下一频道；
- 切台到未预加载频道（菜单跳转等）→ 复用主播放器实例 `stop + setMediaSource + prepare`，
  不重建播放器（实测模拟器冷切 66ms 完成建源）；
- 备用播放器带完整请求头（复用 `TVModel.getMediaSource()`），预加载失败标记坏线并换线
  重试（最多 3 次），失败不打扰主播放；
- 预加载同时 `prewarm(url)` 预热连接（OkHttp 连接池复用，省 TCP/TLS 握手）。

### 3.2 启动首帧快速恢复

- 新增 `hasPlayedSuccessfully`（会话内是否出过画面）：从未出画时，`onPlayerError`
  忽略 30s 冷却与自动换源开关，立即换下一条线路；checkPlaybackRunnable 的停播检测
  同样跳过冷却——稳定源失效不再黑屏 30s；
- 全量线路探测延迟 10s 并保持低并发，把启动带宽让给首帧；
- 主播放器在 Fragment 创建时即初始化（原有），稳定源/兜底频道立即起播（原有）。

### 3.3 设置

- 设置页新增"快速切台（预加载下一频道）"开关，默认开启；弱机/省电可关闭。

## 四、验证证据（模拟器 emulator-5554，API 36）

- 冷切：按切台键 → "Playing tvModel: CCTV2" → "IPTV playback started" 66ms 完成建源，
  随后自动 "Preparing standby for next channel: CCTV3"；
- 备用预加载：电视设备上 standby 正常创建与预加载（v2.9 前电视上完全关闭）；
- 坏线处理：备用预加载失败 → 标记坏线 → 自动换下一条线路重试（≤3 次），主播放不受影响；
- 稳定性：连续 4 次上下切台无崩溃、无 ANR；CCTV1 稳定播放 120s+ 无跳台；
- 单测：30 项全绿。
