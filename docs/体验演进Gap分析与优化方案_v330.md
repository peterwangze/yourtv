# 聚源TV 体验演进：Gap 分析与优化方案设计（v3.3.0）

> 版本基线：v3.2.0（versionCode 320）
> 设计日期：2026-08-09
> 输入：① 全量源数据实测（3763 条线路探测 ×2 轮）② 候选源调研（43 仓库 API + 67 组镜像探测 + 47 个源文件解析，docs 见 tools/research/source_candidates.md）③ 分类误判全量扫描（3763 条真实数据过真实分类器）④ 用户反馈（观看几秒后卡住/像在切源；启动无央视分类；要求聚合反向关联源 + 频道级换源 + 内置预载源开箱即用）⑤ 播放链路代码审计（缓冲策略/自动换线/启动缓存链路）

## 一、调研结论浓缩（数据驱动）

### 1.1 线路存活率（2026-08-09 全量探测，GET Range bytes=0-0，UA VLC/3.0.18，6s 超时，24 并发）

- 两轮全量探测：59.9% → 43.3% 存活（公开源波动大，best-fan 从 88% 跌至 36-42%，存在反爬限流）
- **3763 条线路仅约一半可用；830/1278 个频道的"首选线路"已死**（含 CCTV1-17 全部首选线为 aptv 死链 `101.35.240.114:88`）
- 按分类存活率：央视 42.9% / 卫视 40.8% / 地方 48.5% / 其他 35.6% / 海外 12.5%
- 稳定高质源：vbskycn（87-95%）、zbds（77-90%，国内直连）；严重退化：hououinkami 0%、vicjl 0%（与 BurningC4 字节同源）、jk2024988 咪咕2 0%（HTTP 660 签名过期）、hujingguang 6.7-24%、fanmingming ipv6 14-17%
- 结论：**纯 URL 关键词启发式排序 + 会话级健康缓存无法应对 40-50% 线路腐烂**，必须引入"持久线路健康 + 实测选线 + 源质量分层"。

### 1.2 候选源（详见 tools/research/source_candidates.md）

- **CCSH/IPTV live_lite.m3u（新增首选）**：2026-08-09 当日推送，2233 行 = 390 央视 + 797 卫视 + 711 地方，抽样 86.7-100% 存活、8/8 真 HLS——直接解决"卫视仅 50 频道/地方 86% 单线路"痛点
- **YueChan/Live GNTV.m3u（新增）**：50 频道（浙江地方台+台湾+4K），7/7 存活，噪音 2%
- **YanG-1989/m3u Migu.m3u（新增，需国内验证）**：45 条 cmvideo 咪咕移动 OTT（晴彩/咪咕直播4K），0 噪音
- **suxuang/myIPTV ipv4.m3u（源管理可选）**：1224 行（135 央视/174 卫视/632 地方）但抽样仅 20% 存活
- **移除/降级**：live.fanmingming.cn 两源（SSL 不可达且上游已删 ipv4.m3u 路径）、vicjl、hououinkami China_v4、jk2024988 咪咕2（降级尾部监测）、hujingguang（降级）

### 1.3 GitHub 加速镜像（东京出口 67 组探测）

- 可用：gh-proxy.com（296ms）> github.horsenma.top（311ms）> jsdelivr（304ms，结构不同）> gh.llkk.cc（560ms）> ghfast.top（960ms）> ghproxy.net（1.07s）
- **现 App 11 个镜像中 7 个已失效**（moeyy/ghp.ci/ghproxy.click SSL EOF、ghproxy.cc 系证书过期、ghproxy.cn 假 200 HTML、gh.ddlc.top 429、gh.con.sh 被封），且列表前 3 位中 2 个不可用，拖慢首源加载

### 1.4 分类误判全量扫描（3763 条真实数据过真实 ChannelClassifier）

- **短英文关键词子串误匹配是主根因**：
  - `inter`（乌克兰关键词）命中 "International" → Zhejiang TV International/Dragon TV International 被分到 乌克兰/俄罗斯
  - `ary`（巴基斯坦）命中 "documentary" → 发现之旅 → 巴基斯坦
  - `n tv`（俄罗斯）命中 "Dragon TV" 词尾 → 俄罗斯
  - `ert`（希腊）命中 hint "Entertainment" → Channel U/TDM 等 9 条 → 希腊
  - `rts`（塞尔维亚）命中 hint "Sports" → TDM Sports → 塞尔维亚
  - `ntv`（日本）命中 "CGNTV" → 日本
- **咪咕体育每日轮换分组误分**：240+ 条赛事（"体育-今天05-10"组，标题含 广东/日本/法国 等队名）被分到 地方-省份/海外-国家，实际全部应为 其他-体育
- **卫视分组提示误判**：五星体育/山东教育/苏州4K/重温经典 在"卫视IPV4/卫视频道"分组下被归为卫视（实为 上海体育/山东教育/江苏苏州/央视）
- **县市/区县映射缺失**：灌阳（广西）、高台（甘肃）、和政（甘肃）、房山（北京）、白城（吉林）、珲春（吉林）、江津（重庆）等 7 处落"其他"
- **无分组付费/专题频道落"其他-其他"**：发现之旅/中学生/财富天下/环球旅游/中华特产/中国天气/都市剧场/数码时代 等 8 个
- **内置兜底源 R.raw.channels 为上游旧加密列表**，分组名为乱码（"央视频道"被误解码为 "رًتس"）——启动兜底时分类展示异常

### 1.5 播放"几秒后卡住/像在切源"诊断（代码审计）

- **缓冲配置过激进**：`createFastLoadControl` = 500ms 最小缓冲 / 300ms 起播缓冲，公网直播流轻微抖动即进入 BUFFERING
- **缓冲事件计数触发换线过敏感**：`onPlaybackStateChanged` 中 10 秒内 5 次缓冲事件或累计 8 秒缓冲即静默 `sourceUp` 换线（配合 500ms 缓冲几乎必触发）
- **停播检测无"本次已出画"门槛**：`checkPlaybackRunnable` 中"2.5 秒未播放即换线"对**首次起播中的缓冲**同样生效（`!hasPlayedSuccessfully` 时也触发），换线后再次 2.5s 未出画又换 → 进频道后 2-3 秒一换的"卡住+切源"观感，正是用户反馈现象
- **选线不感知真实健康**：`rankChannelUris` 只按 URL 关键词 + 会话级探测排序，40% 死线排在前面（实测 CCTV1-17 首选均为 aptv 死链）
- **备用播放器预加载时机**：主播放刚出画立即预加载下一频道，弱网下与主播放抢带宽

### 1.6 启动无央视分类诊断（代码审计 + 数据）

- 启动链路：`channels_list_cache_v290.json`（聚合缓存）→ 激活源缓存 → 旧 codechannels.txt → R.raw.channels（乱码旧表）
- **二次启动后不再重新聚合**：`importDefaultsIfNeeded` 在 configUrl 已设置时直接返回；`updateConfig` 只把激活源导入 `aggregateBuffer` 而**从不触发 `aggregateAllSources`**；`aggregateRemainingSources` 只在首装/手动刷新路径被调用 → 列表长期停留在某次快照（可能是单源/旧版缓存）
- 首次安装时 `applyGate` 让"第一个成功源"立即整体替换列表，若随后聚合被中断/网络差，缓存就是单源小列表
- 兜底源 R.raw.channels 分组乱码 → 兜底时看不到正常分类

## 二、Gap 分析（按用户诉求收敛为 6 个主 Gap）

| # | Gap | 证据 | 影响 |
|---|---|---|---|
| G1 | **架构：源=隐藏设置，非"聚合→反向关联源"** | 用户反馈 + 代码：源管理切换=整体替换列表；线路列表不显示来源 | 用户困惑、换源破坏聚合结果 |
| G2 | **开箱即用无保障**：无内置预载列表，首装/兜底依赖网络或乱码旧表 | 1.6 + R.raw.channels 乱码实测 | 首装无网=看不到分类/频道 |
| G3 | **进频道几秒后卡住/反复切源** | 1.5 三个根因（缓冲 500ms、事件计数换线、停播无门槛） | 核心体验恶化 |
| G4 | **非央视加载慢**：40-50% 线路死、首选死线、卫视/地方覆盖不足（卫视仅 50 频道、地方 86% 单线） | 1.1/1.2 实测 | 卫视/地方频道黑屏等待 |
| G5 | **分类错误**：短关键词误匹配、体育赛事误分、县市缺失、卫视提示误判 | 1.4 全量扫描 | 导航混乱 |
| G6 | **源治理缺失**：7/11 镜像失效、4 源 0% 存活、fanmingming 路径已删 | 1.2/1.3 实测 | 首源加载慢、聚合噪音 |

## 三、优化方案设计（v3.3.0 承载）

原则：现有功能与性能不退化；改动可独立回滚；所有改动先过单测再上模拟器实测。

### 3.1 架构演进：聚合为唯一列表，源反向关联到频道（G1）

- 可见频道列表**永远**是多源聚合结果（`aggregateAllSources` 产出），任何单源导入不再整体替换列表
- `TV` 增加 `uriSources: Map<String, String>`（线路 URL → 源名），解析/合并时逐线路携带来源标注
- 频道级换源体验升级：线路选择面板（SourceSelectFragment）每行显示 **源名 + 清晰度 + 延迟**；右键换线语义不变
- "源管理"（SourcesFragment）改为**聚合源管理**：启用/停用参与聚合的源、全部刷新、增删自定义源；"切换源"不再替换列表，仅调整聚合优先级并重新聚合

### 3.2 内置预载源快照，开箱即用 + 失效才更新（G2）

- 新增 `app/src/main/assets/bundled_channels.json`：发布时用 `tools/build_bundled.py` 从实测源生成（聚合→过滤→分类→按存活率+质量排序，每频道线路上限 10 条），**用户安装后立即有完整分类列表（央视/卫视/地方/海外/其他），零网络依赖**
- 启动链路调整：缓存 → 内置快照 → 激活源缓存 → 旧兜底；快照应用后置位 channelsOk，首频道立即起播
- 后台刷新策略：启动后延迟执行"源刷新"（24h 内不重复），下载+解析+聚合完成后**整体替换**列表并原子写缓存；失败保留现有列表（不退化）
- "明显失效才更新"：线路健康持久化（见 3.4）后，若播放频道全部线路死 → 触发一次增量源刷新

### 3.3 播放缓冲与换线策略修正（G3，用户反馈"几秒后卡住"）

- 缓冲参数 `500/2000/300/500` → `1500/6000/750/1500`（直播秒开与抗抖动平衡，实测校准）
- 停播换线增加"本次播放已出画"门槛：`playbackStartTime > 0` 才允许 2.5s 停播换线；**首次起播缓冲交给 8s 首帧看门狗**（语义单一，杜绝"2-3 秒一换"）
- 缓冲事件换线阈值收紧：10 秒 5 次 → 15 秒 8 次，且累计缓冲 8s → 10s；单频道会话内自动换线上限 5 次
- 备用播放器预加载延迟到主播放稳定后（出画 ≥3s）再启动，避免抢带宽

### 3.4 选线自动选优（G4 核心）

- **线路健康持久化**：LineHealth 结果持久化（url→(ok,latency,时间戳)，24h TTL，上限 2000 条），跨会话记忆死线
- **起播前快速实测选线**：目标频道线路 ≤6 条且非全部已知健康时，并行 Range 探测（2.5s 上限）；有已知健康线则直接使用并后台补测
- **聚合排序引入源质量分层**：rankChannelUris = 持久健康 > 源质量分（zbds/vbskycn/CCSH 高权，migu/运营商中权，iptv-org/aptv 低权）> 清晰度 > 延迟
- 备用播放器选线同规则（跳过持久死线）

### 3.5 分类修复（G5，全量扫描驱动）

- `containsKeyword` 词边界匹配：短英文关键词（inter/ary/n tv/1tv/true/ert/rts/ntv 等 40 个）不再子串误匹配，数字后缀品牌（BBC1/KBS1）保留兼容
- 前置规则：咪咕"体育-今/明/昨/后天xx-xx"分组 → 其他-体育（先于国家匹配，240+ 条赛事归位）；重温经典 → 央视
- 卫视分组提示纠偏：五星体育→上海、山东教育→山东、苏州/苏州4K→江苏（标题为已知城市名时优先于"卫视"分组提示）
- 别名补充：Zhejiang/Dragon/Hunan/Jiangsu/Beijing/Shanghai/Shenzhen/Guangdong "TV International" → 对应卫视；Channel U→香港；TDM→澳门；meWATCH→新加坡；CGNTV→韩国
- 县市映射补充 7 处：灌阳→广西、高台→甘肃、和政→甘肃、房山→北京、白城→吉林、珲春→吉林、江津→重庆
- 无分组专题频道归类：发现之旅→纪录、中学生→教育、财富天下→财经、环球旅游→旅游、中华特产→生活、中国天气→天气、都市剧场→电影、数码时代→数字电视

- `SP.DEFAULT_SOURCES` 重构（按优先级）：
  1. live.zbds.top/tv/iptv4.txt（国内直连）
  2. vbskycn/iptv iptv4.m3u
  3. **CCSH/IPTV live_lite.m3u（新增）**

  5. **YueChan/Live GNTV.m3u（新增）**

  7. migu-sports 三源合并（保留，回放过滤已具备）
  8. iptv-org cn/zho/hk/tw/mo（保留）
  9. aptv iptv.m3u（保留+噪音过滤已具备）
  10. live.fanmingming.com ipv6.m3u（IPv6 用户）+ index.m3u（替换已删路径的 fanmingming.cn 两源）

## 四、回归基线（不退化承诺）

1. 单元测试全绿（ChannelClassifier/ChannelMetadataParser/SourceQuality + 新增用例，debug+release）
2. 全新安装（断网）：内置快照立即出完整分类列表，首频道秒开
3. 全新安装（联网）：快照先出 → 后台聚合升级，列表不闪断、当前频道锚定不漂移
4. 进频道连续 20 次：无"2-3 秒一换"式卡顿；死线首跳 ≤8s（首帧看门狗），活线首帧 ≤3s
5. 无缝切台/备用预加载仍生效；CCTV1 播放无覆盖、无比例错误（v3.2.0 基线）
6. 搜索/最近观看/收藏/EPG/定时关机/画面比例/三级导航全回归
7. 分类抽样验证：咪咕体育全部归"其他-体育"；Dragon/Zhejiang TV International 归卫视；五星体育/山东教育/苏州归地方；灌阳/高台/白城归对应省份
8. 内存/ANR：聚合窗口内连续按键无 ANR
