# 实施路线、验证门槛与发布回滚

状态：待实施计划。审计与设计本身的实际验证见 [validation.md](evidence/validation.md)；下列目标均不是本次测得的成绩。阶段按依赖排序，不以未知人员规模承诺工期。

## 1. 工作包与完成定义

```mermaid
flowchart LR
  M0[M0 可复现基线与诊断] --> M1[M1 观看会话与有限恢复]
  M1 --> M2[M2 本地目录与三网源治理]
  M2 --> M3[M3 完整遥控器与功能闭环]
  M3 --> M4[M4 三网真机验收与逐批发布]
```

UI 草图、离线测试 fixture 和真实网络采样准备可提前开展；合并与开关启用遵守依赖。每个工作包以可单独验证、可关闭或回退的小提交推进，不一次替换整个应用。

| 阶段 | 工作包与对应审计 | 完成定义 | 回退边界 |
|---|---|---|---|
| M0：建立证据 | 拆出无断言研究任务和绝对路径；固定 fixture；CI 单测/debug 构建；只读事件/流量诊断；统一依赖声明、AAR 来源哈希及版本编码（A02/A27/A28） | 任意干净工作区单测不改受控文件；记录 resolved 依赖与 APK 信息；旧行为有可重放故障用例和首帧/缓冲基线 | 诊断开关可关闭；不改 ID/schema/源清单；库大版本升级另开工作包 |
| M1：先保证观看 | 播放/浏览 ID 分离；coordinator 统一错误、首帧、重试、切线与取消；单线路恢复；网络失联；解码重建恢复；Lifecycle/音频焦点；修正一次性定时（A01–A05/A20/A21/A26） | 故障状态机与 stale callback 测试通过；无跨频道恢复/双音频；起播/恢复预算有终态；自动换线关闭确实有效；API 23 与参考电视跑通 | coordinator 开关切换必须先停旧会话，任何时刻只有一套恢复写入者；错误严重可通过本地策略关闭自动换线 |
| M2：数据与网络 | 源 enabled/scope；可取消 HTTP；每源 LKG/原子提交；身份/番号迁移；EPG ID；分网络健康、DNS 失效、有效请求头、低带宽维护；配对服务关闭默认常驻；TLS 恢复（A06–A15/A17/A18/A23–A25） | 杀进程/坏数据/取消/部分源失败不丢目录收藏；LAN 用户源可导入；网络变化不复用旧失败；所有维护受预算；字段往返不丢请求头 | 先原子文件、再 Room 独立迁移；目录 generation 可退；用户新增偏好不随目录回退；TLS 失败走诊断而不恢复 trust-all |
| M3：交互闭环 | OverlayHost/FocusController；五向搜索、频道操作、番号码表；EPG/线路详情；音轨字幕/比例；源管理与诊断；Web adapter 收敛（A16/A19/A22/A24/A26） | [交互脚本](03-experience.md#8-端到端体验验收脚本) 全部执行并留截图/录像与按键记录；右键旧习惯有迁移；旧 Web 专属行为有替代测试 | UI/旧右键偏好独立开关；不同时切换 UI 框架；未迁移 Web 能力保留适配入口 |
| M4：实网发布 | 三网、地区、设备矩阵；源资格记录；长播与故障注入；离线升级回退演练 | 下面门槛满足；每个不支持场景有明确产品范围；发布包哈希、签名、versionCode、数据兼容性可核对 | 本地开关/上一代目录/更高 versionCode 修复包；无远程服务也能恢复 |

M0 的解析基线不能拖延已确认的观看修复；M1 可先修 A01 的真实播放引用、预算和定时等小范围问题，再切 coordinator。M2 中 EPG 归属与事务属于正确性修复，优先于自动评分算法调优。M3 之前就可交付已独立验证的编号/搜索修复，不以视觉重做阻塞可用性。

建议职责按角色分配：播放实现维护状态机和故障证据；数据/网络实现维护 schema、源与导入契约；交互实现维护按键/焦点表；验证负责人维护样本与发布门槛。角色可以由同一人承担，不能因此省略交叉核对。

## 2. 观测口径

一个 `tuneAttempt` 从用户确认目标（或开机恢复命令）开始，到该目标真实出画/失败/被用户取消结束。内部换线是同一目标的子 attempt，不能把每条失败线路拆成独立成功会话美化结果。`watchSession` 从该目标命令开始，直到主动离开该频道/停止/应用退出；卡顿不会重开会话。以下均同时附样本数、网络档案、设备档案、版本与时间。

| 指标 | 定义与分母 |
|---|---|
| 目录可操作时间 | 进程启动到本地目录首屏可见且能移动焦点；首次安装与已有缓存分别统计 |
| 首帧时间 TTFF | 播放意图确认到相同 session/目标 Surface 的第一帧；开机与热切台分开；旧频道残留画面不算 |
| 视听就绪 | 视频首帧且音轨开始正常推进/输出；使用播放器音频事件作为代理，真机抽样人工核验声音/同步；静音节目不凭能量阈值误判 |
| 起播成功率 | 在 20 秒预算内视听就绪的目标次数 / 所有未主动提前取消的目标次数；另报提前取消数/率和发生时长，取消不能被隐去 |
| 卡顿时间比 | 首次出画之后非用户暂停的不可播放时长 / 应观看时长；恢复/换线黑屏计入，后台/待机/用户暂停剔除 |
| 中断事件 | 出画后单次不可播放超过 2 秒；保留 0.5–2 秒短卡顿另计；恢复动作本身不是成功 |
| 无长中断会话比例 | 30 分钟观察窗口内无超过 2 秒中断且无不可恢复失败的窗口 / 全部合格 30 分钟观察窗口；提前因失败结束算失败窗口 |
| 故障恢复时间 | 可观测中断开始至同频道视听恢复；网络断开时同时报告断网持续时间及系统报告回网后恢复耗时 |
| 交互延迟 | 遥控器输入到目标焦点/目标频道名完成一帧可见更新；与网络出画时间分开 |
| 取消延迟 | Stop/新播放意图/任务取消发出到旧请求关闭、旧结果不可提交；区分逻辑立即失效与底层 I/O 关闭 |
| 网络开销 | 媒体与控制请求分别记请求数、线上字节、解压后字节、重试；无法归因的流量单列，不能排除统计 |

TTFF 只给成功样本的 p50/p95 时，必须同列成功率、失败数及取消数。30 分钟窗口不能只挑已经成功长播的会话；预先登记测试目标和窗口。按网络×设备分组展示，避免所有高速设备合并后掩盖移动某地/老 ARMv7 的失败。

## 3. 首轮产品门槛

参考设备与线路样本在 M0 固定并记录。已验证可播线路指本设备/本网络近期有 E3/E4 证据，且测试时源正常供给；可控媒体 fixture 用于隔离客户端性能。源本身中断仍计入现场端到端报告，再单独给原因归类，不能从报告删除。

| 项目 | 首轮目标 / 门禁 | 条件与解释 |
|---|---|---|
| 本地目录 | p95 ≤1.5 秒 | 已缓存、参考设备；断网也测；低端设备独立报告 |
| 热切台 / 冷启视听就绪 | p95 ≤4 秒 / ≤6 秒 | 近期验证线路及足够吞吐；固定 HLS 分片/GOP 条件并记录；不是任意公共源承诺 |
| 有界失败 | 起播 ≤20 秒、播放中故障恢复 episode ≤12 秒后有可操作终态 | 不把相关订阅修复暗中延长为无限加载；独立修复任务最多 20 秒并有进度/取消 |
| 可靠起播 | 参考网络中 ≥98% 在预算内成功 | 每个网络格至少 100 次预定切台；小样本附分子/分母，不能表述为全国可用率 |
| 连续观看 | 卡顿时间比 ≤0.5%；30 分钟无长中断窗口 ≥95% | 作为扩大样本后的发布目标；初轮不足 20 个窗口的格只作筛查并公布原始结果，不据此宣称达标 |
| 交互 | 焦点/目标提示 p95 ≤100ms | 纯五向连续 100 次输入，不包括等待视频；大字体和目录更新同测 |
| 取消 | 逻辑失效立即；旧控制 I/O p95 ≤500ms | 可控挂起服务器下测；无旧回调提交/无后台继续整段下载 |
| 数据正确性 | 0 个误频道恢复、收藏错配、取消后提交、有效目录被空数据替换 | 所有确定性故障 fixture 必须通过，不以平均值抵消 |
| 资源 | 无 ANR/OOM/双音频；前台单引擎；连续 2 小时内存无持续上升趋势 | 记录 PSS/Java/native/解码/温度，预热后分段比较；M0 确定各设备上限，未给上限即不通过资源门禁 |
| 流量让路 | 冷启/切台/重缓冲新增自动维护请求为 0；已有维护立即取消 | 相关播放必需鉴权另归媒体依赖；稳定自动维护按 64KiB/s、2MiB/小时初值验证 |
| 生命周期 | 50 次 HOME/返回与 20 次待机/唤醒无错台、崩溃或后台偷播 | 系统强杀恢复、音频焦点抢占、HDMI 输出变化另有脚本 |

参数允许经实测修订，但需要记录原值、证据、受影响设备和收益/退化；不能仅为让失败变绿而延长起播超时或删除困难频道。新增受控码率、连接策略、预加载均单变量实验。

## 4. 中国大陆电信/联通/移动采样

### 4.1 网络格与时间

最少覆盖三家固定宽带，每家两个省份，共六个网络格；优先用户实际家庭所在地区，未提供时招募有明确记录的测试点。每格记录省份、用户确认运营商、接入类型（光纤/有线、Wi-Fi/以太网）、设备、IPv4/IPv6 实际可用性、代理/VPN 状态。运营商信息不从 SIM 或 URL 猜测，不收集家庭公网 IP 作为公开报告字段。

首轮连续三天同时覆盖非高峰与当地 19:00–23:00。测试安排均以相同版本、固定预登记频道集进行；不把云主机、公司专线或代理出口当作家庭三网样本。每格至少：

- 20 个预登记频道（央视、卫视、该省地方台及必要长尾）×5 次切台，共 100 次，分散在时间窗口；分别统计内置默认选择和人工已知可播线路。
- 5 个重要频道各一次 30 分钟窗口，分布在晚高峰与非高峰；这是问题筛查的最低量。需要宣称达到 95% 连续观看目标时，将每格扩到至少 20 个独立窗口，跨至少三天并保留失败窗口。
- 一次 2 小时连续播放，观察内存、温度、音画同步、目录维护与 token/清单时效；试发布阶段对主要设备再做至少一次 8 小时长播。若要声称跨天稳定，增加覆盖相应时长的样本。

六格是最小覆盖，不能外推全部省份。统计报告标明“哪些频道、哪些网络、何时验证”，同时公开未覆盖格；某格不通过则优化该格策略或缩小该地区推荐目录，不能用其他五格均值掩盖。

### 4.2 源资格记录

每条推荐线路保留：ChannelId/LineId、来源版本、授权/使用范围（按来源声明核对）、验证日期、省份/运营商、设备/codec、E1–E4、首帧分布、有效观看时长、卡顿/错误及故障域。真实 URL/请求头保存在受控配置，报告用脱敏引用。

重要频道目标是至少两个**实际独立故障域**的合格候选；不足时标单线路或候选不足，不用同上游镜像凑数。E4 的至少 3 次/合计 30 分钟仅是最低采样条件，还须卡顿/错误满足质量门槛才显示“本网络较稳定”。过期或新网络降级为历史证据，不能永久盖章。

内置生成流水线需要固定输入 hash、schema、过滤规则、构建版本和网络证据；替换当前缺失的 `probe_lines_results.json` 隐式依赖。原始采样大文件可放受控附件/制品库，但小型契约 fixture 和清单必须在 Git 可复现；没有有效样本的内容标“候选”。更新订阅下载成功不改变 E3/E4。

### 4.3 网络故障与预期

| 场景 | 如何验证 | 应有行为 |
|---|---|---|
| 断网 5/30/120 秒后恢复 | 测试路由/隔离设备断连，记录系统事件 | 缓冲耗尽后等待；不耗尽所有候选；回网同频道恢复一次 |
| DNS 超时、旧解析、IPv6 有地址但不可达 | 受控 DNS/路由配置；IPv4/IPv6-only/双栈分别记录 | 有界回退，网络变化清缓存；系统验证失败不禁止真实可达线路 |
| 吞吐低于码率、突发抖动 | 本地受控限速，阶梯 0.7×/1.2×/2×媒体码率；延迟 50/150/300ms 与丢包 1%/3% | 低吞吐下选择确有低码率候选或给明确失败；不承诺客户端能消除带宽缺口 |
| Wi-Fi/有线切换、代理变化 | 测试设备切换，源端日志核对新连接 | 新代次、取消旧请求、旧失败不污染；当前可用缓冲尽量保留 |
| 某 host/提供方整体故障 | 本地 fixture 映射多个镜像到同故障域 | 尝试独立故障域；滚动跨线预算不被镜像绕过 |
| 目录站不可达但媒体正常 | 禁用订阅服务，保留媒体端点 | 当前播放、搜索、收藏正常；手动更新有失败终态 |

受控网络实验只在测试设备/路由环境执行，不能为自动诊断修改用户路由、DNS 或扫描整个局域网。实际 ISP 差异必须由现场采样证明。

## 5. 设备与媒体兼容矩阵

| 设备层 | 必测内容 | 验收限制 |
|---|---|---|
| Android 6/API 23，ARMv7，约 1GB 低端电视/盒子 | H.264/AAC 720p/1080p、硬解枚举、长播内存、五向输入、大字体 | 不以强制软解使首帧“成功”却持续掉帧；HEVC/4K 不作默认要求 |
| API 26–28，32/64 位老设备 | 生命周期、WebView 版本、证书/时钟、HEVC 可用性 | X5 缺失/不可下载仍能看原生频道 |
| API 29–33，ARM64，约 2GB 主流电视 | 1080p25/50、音画同步、HDMI/扬声器、待机恢复 | 50Hz/60Hz 显示与输出帧率分别记录 |
| API 34–35 及发布时可取得的新系统 | target 35 生命周期/权限、4K/HDR 能力、字幕音轨、升级安装 | 支持范围按实际测试标记，不因 API 高就假定 codec 支持 |
| Android TV 模拟器 | 焦点/流程、故障 fixture、布局快照 | 不替代 ARM 解码、温控、家庭路由和遥控器真机 |

媒体 fixture 至少含 HLS master/variant、相对路径/重定向、AES key、长 GOP、清单窗口推进/过期、HTTP-TS、H.264/AAC、HEVC（支持设备）、不支持音轨、有声无视频、视频停止而音频推进。音频广播如保留，应有明确 channel capability，不能以视频首帧规则给广播判死；本轮默认推荐目录是电视视频频道。

RTSP/RTMP/UDP/RTP、Web 网页、回看分别声明能力和测试结果。存在 URI 解析分支不等于端到端兼容，不能继续用“格式全兼容”代替矩阵。

## 6. 自动验证与故障注入

| 测试层 | 必须新增的有效断言 | 执行时机 |
|---|---|---|
| 纯 Kotlin | 状态机 FakeClock：重复错误、旧 attempt 回调、单线恢复、全坏有界、autoSwitch=false、用户取消、滚动预算 | 每次相关变更/CI |
| 解析与身份 | 标准 JSON、TXT/M3U、BOM/CRLF、请求头 round-trip、content URI adapter、ID/番号冲突、同名不同地区、enabled/tombstone | 每次相关变更/CI |
| 质量与网络 | 严格 IP 判别（fc/fd 开头普通域名）、LAN/public scope、网络画像隔离、DNS 失效、探测失败不覆盖真实成功、故障域去重 | 每次相关变更/CI |
| HTTP fixture | MockWebServer 等本地服务器：200 HTML、416、401/403/429/5xx、挂起响应/取消、重定向头泄露、gzip 超限、有效/停止更新 HLS | 每次网络/播放变更；依赖版本固定 |
| 存储与迁移 | 在写临时/校验/提交/通知各阶段中断；并发刷新旧结果、磁盘不足；旧 ID 歧义、新增收藏、回滚包读新 schema | M2 必须，schema 变化重跑 |
| EPG | 多 channel 后 programme、乱序、多语言/缺 stop、跨日/+0800/UTC、重复 ID/重叠、过期缓存 | 每次解析/查询变更 |
| UI 仪器测试 | 只用 DPAD 的搜索/收藏/编号/源导入；连续 BACK；浏览中故障；刷目录时焦点不跳/不播放 | 每次焦点/界面变更 |
| 真机媒体 | 首帧、音画同步、丢帧、解码 fallback、Surface 重建、音频焦点、待机与长播 | 每个候选发布版本 |

不为每个简单样式值写镜像式测试；需要测试的是用户行为、状态时序、数据契约和失败后的不变量。研究探测不混入单测：显式命令、可注入输入/输出路径、不依赖公网、不改 Git 工作区。构建 CI 先运行离线 fixture；公网节目源探测另行计划，不让外站故障随机打红代码构建。

## 7. 发布、回滚与文档维护

首个候选包先在自用/测试电视验证，再扩到少量同意参加的用户，最后逐步扩大（例如 5%→20%→全部；用户数很少时用设备名单）。目前没有已建遥测后端，门槛可由本地日志导出和人工汇总完成；上传必须独立选择。阶段扩大以经过完整晚高峰与长播观察窗口为前提，不能只按百分比机械推进。

每个候选包保留：Git commit、versionName/versionCode、签名证书指纹、APK SHA-256、依赖锁定结果、schema/policyVersion、数据迁移演练、设备/网络报告、已知限制、上一可用目录和本地策略开关说明。发布文案仅陈述通过范围，不把设计目标写成“已全面实现”。

回滚演练必须涵盖：

1. 无网络启动，关闭新恢复/自动维护策略，仍可看本地目录和进入设置。
2. 新目录异常，原子切回上一可用 generation，当前媒体 request 不被清空，新增收藏不回退。
3. 新 schema 后安装修复包（更高 versionCode），可读取新数据或受控导入兼容快照；不依赖直接安装低版本 Android APK。
4. 用户升级后改变收藏/源启用状态，再回退实现，用户改动仍保留；旧文件清理仅在迁移成功与观察窗口后执行。
5. 新旧播放实现切换时先取消会话并停止输出，再创建另一实现；不存在双策略、双音频或两个媒体下载器。

任何确定性错台/数据丢失/ANR/OOM 阻止扩大；TTFF、卡顿、流量和故障率以同网络同设备基线比较，出现明显退化先缩小变量并回退相关策略。回滚不重新开启不受控 TLS 或无认证远程写入。
