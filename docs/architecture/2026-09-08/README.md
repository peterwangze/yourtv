# 聚源 TV：以观看体验为中心的架构演进设计

审计开始：2026-09-08；归档完成：2026-09-09（保留开始日期作为目录名）。代码基线：`1b47d7446074b9bf26931e8ed0945c6a6630723d`（v3.4.0）。文档状态：**设计完成，待实施及实网验收**。本次提交包含审计、设计、复核证据，不代表应用已经完成这些改造。

## 结论与实施顺序

当前应用已经具备多源聚合、内置目录、收藏、最近观看、节目单、线路选择、画面比例和定时停止的基础。体验反复的主要原因是：播放策略分散、观看状态与浏览状态混用、源质量证据不足，以及目录/节目单/网络维护没有形成一致的数据契约。继续叠加播放器超时和硬编码源权重，难以稳定改善观看。

下一阶段按以下顺序推进：

1. **观看连续性**：单一播放会话状态机、真实首帧和卡顿统计、有限恢复预算、单线路重试、设备解码能力适配。
2. **三网源质量与本地可用性**：按网络保存播放证据，目录事务更新，公开源与用户局域网源分开准入；维护任务可取消且不长期饿死。
3. **遥控器交互与常用功能闭环**：播放与浏览分离、单一浮层焦点、五向遥控器搜索、稳定频道编号、正确 EPG、可理解的错误恢复。
4. **持续验证**：先补可重复故障测试，再在电信/联通/移动家庭宽带与老电视上验证；通过门槛后逐批发布。

“降低网络依赖”的具体含义是：目录、导航、收藏、设置、已缓存节目单离线可用；联网时播放流量优先，控制数据少量更新。**实时直播仍需要持续可达、具有足够吞吐的媒体线路；缓存频道地址不等于缓存节目内容。**不作“断网也能直播”或“公共源全国三网保证可用”的承诺。

## 范围和假设

- 优先场景为中国大陆家庭电视直播，电信/联通/移动固定宽带，五向遥控器，非 Google 服务依赖设备。
- 兼容基线沿用仓库声明的 Android 6.0/API 23；ARMv7/ARM64 和低内存电视优先，模拟器只辅助验证。具体型号、省份、运营商线路及家庭观看清单尚未提供，见验收计划中的补充采样要求。
- 本轮为全仓静态盘点和主要路径深入审计，不是对闭源 AAR、每个外部节目源或所有设备行为的证明。扫描信号仅辅助定位，结论有独立代码证据。
- 不在本轮更换直播源、修改运行代码、升级播放器、发布 APK 或推送远端。先将可实施设计和证据作为独立 Git 提交归档。
- 历史调研保留原位。本归档针对 v3.4.0，后续设计入口以本目录为准；历史性能数字、镜像可用率不能代替当前三网测试。
